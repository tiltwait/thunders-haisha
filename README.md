# サンダース配車費

時津サンダースの配車費（クルマでの移動が必要な試合で、配車当番でない家庭から集めて配車した家庭・指導者に支給するお金）を、スマホで集金・支給チェックするWebアプリです。

- 画面：GitHub Pages（このリポジトリ）
- ログインとデータ保存：Firebase（Authentication ＋ Cloud Firestore、無料の Spark プラン）

## 計算ルール（令和9年度〜）

| 項目 | 内容 |
|---|---|
| 単価 | 行先の往復距離で決まる（50km以内 500円 / 79km以内 800円 / 80km以上 1,000円） |
| 集金額 | 単価 × 集金対象の部員数（部員1人ごと） |
| 欠席 | 当日欠席した部員は集金しない |
| 配車当番の世帯 | 集金を免除。兄弟がいる場合は1人分だけ免除し、残りは集金 |
| 1台あたり | 集金額 ÷ 配車台数（保護者＋指導者）を **100円未満切り捨て** |
| あまり | プールへ（駐車場代・指導者の昼食代補助に使う） |
| 有料道路 | 使用の有無に関係なく、配車した全員に同じ額を支給 |

出典：「配車システム変更について」「配車代一覧」（2026年10月12日付）

## 役割

| 役割 | できること |
|---|---|
| 管理者 | すべての編集、IDの発行・権限変更・削除 |
| 担当者 | 試合・集金・支給・プール・名簿の編集 |
| 閲覧 | 見るだけ |

権限は Firebase のセキュリティルール（`firestore.rules`）でサーバー側でも強制しています。

## 個人情報の扱い

- **このリポジトリには部員の氏名などの個人情報を一切置きません。** 名簿はアプリの「設定 → 名簿ファイルの読み込み」から Firestore に登録します。
- `.gitignore` で名簿・CSV・Excel・PDF をコミットしないようにしています。
- `config.js` の Firebase 設定値は秘密情報ではありません（Firebase 公式：API keys for Firebase services are OK to include in code）。データはログインとセキュリティルールで守ります。
- ログアウトすると、その端末に一時保存された名簿と記録も消去します。

## 初回セットアップ

1. Firebase コンソールでプロジェクトを作成
2. Authentication →「ログイン方法」で **メール/パスワード** を有効化
3. Authentication →「設定」→「承認済みドメイン」に `＜GitHubユーザー名＞.github.io` を追加
4. Firestore Database を作成（ロケーション `asia-northeast1`、本番環境モード）
5. Firestore →「ルール」に `firestore.rules` の内容を貼り付けて「公開」
6. プロジェクトの設定 →「マイアプリ」でウェブアプリを登録し、表示された値を `config.js` に貼り付け
7. GitHub リポジトリの Settings → Pages で `main` ブランチの `/ (root)` を公開
8. 公開されたURLを開き、**初期設定画面で管理者のIDとパスワードを作成**（最初の1回だけ表示されます。公開したらすぐに行ってください）
9. 設定 →「名簿ファイルの読み込み」で名簿ファイル（.json）を読み込み、「保存する」
10. 設定 →「IDの発行と権限」で担当者・保護者のIDを発行し、URLとIDを配る

## 名簿ファイルの形式

```json
{
  "format": "haisha-roster-v1",
  "households": [{ "id": "h01", "name": "〇〇家" }],
  "members": [{ "id": "m01", "no": 8, "name": "〇〇 〇〇", "hh": "h01", "active": true }]
}
```

兄弟は同じ `hh`（世帯）にします。部員がやめたときは削除せず `active: false`（画面では「在籍」を外す）にします。

## ログインIDについて

ログインIDは `ID@haisha.example.com` というメール形式に変換して Firebase に登録しています（メールは送信されません）。ドメインは `config.js` の `loginDomain` で変えられます。パスワードを忘れた人には、新しいIDを発行して古いIDを削除してください。
